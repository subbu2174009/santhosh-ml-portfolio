Chapter 3: Perceptron Convergence on 2D Clusters Model from Scratch

Analytical Formulation: The Perceptron activation is given by $f(z) = 1$ if $z \ge 0$ else $0$, where $z = \mathbf{w}^T\mathbf{x} + b$. Weights update sequentially: $\mathbf{w} \leftarrow \mathbf{w} + \eta(y - \hat{y})\mathbf{x}$ and $b \leftarrow b + \eta(y - \hat{y})$. Convergence is guaranteed in finite steps if the dataset is linearly separable. 

import numpy as np

class Perceptron:
    def __init__(self, learning_rate=0.1, max_epochs=100):
        self.lr = learning_rate
        self.max_epochs = max_epochs
        self.weights = None
        self.bias = None

    def fit(self, X, y):
        n_samples, n_features = X.shape
        self.weights = np.zeros(n_features)
        self.bias = 0.0
        
        for epoch in range(self.max_epochs):
            errors = 0
            for idx, x_i in enumerate(X):
                linear_output = np.dot(x_i, self.weights) + self.bias
                y_predicted = 1 if linear_output >= 0 else 0
                
                # Weight update rule
                update = self.lr * (y[idx] - y_predicted)
                if update != 0:
                    self.weights += update * x_i
                    self.bias += update
                    errors += 1
            if errors == 0:
                print(f"Converged at epoch {epoch}")
                break
        return self

    def predict(self, X):
        linear_output = np.dot(X, self.weights) + self.bias
        return np.where(linear_output >= 0, 1, 0)

# --- Synthetic Linearly Separable Data ---
X_train = np.array([[1.5, 2.2], [2.1, 3.5], [0.8, 1.2], [3.5, 4.8], [0.5, 0.7], [1.1, 0.9]])
y_train = np.array([1, 1, 0, 1, 0, 0])

model = Perceptron(learning_rate=0.05, max_epochs=50)
model.fit(X_train, y_train)
print("Final Weights:", model.weights)
print("Final Bias   :", model.bias)

Chapter 4: Gradient Descent & Linear Regression Vectorized Optimization

Analytical Formulation: The Mean Squared Error cost is $J(\mathbf{w}, b) = \frac{1}{2N}\sum (y_i - (\mathbf{w}^T\mathbf{x}_i + b))^2$. Gradients are computed as $\frac{\partial J}{\partial \mathbf{w}} = \frac{1}{N}\mathbf{X}^T(\mathbf{y}_{pred} - \mathbf{y})$ and $\frac{\partial J}{\partial b} = \frac{1}{N}\sum(y_{pred} - y_i)$. Parameters update iteratively: $\mathbf{w} \leftarrow \mathbf{w} - \alpha \frac{\partial J}{\partial \mathbf{w}}$. 

import numpy as np

# --- Generate Synthetic Regression Dataset ---
np.random.seed(42)
X = 2 * np.random.rand(100, 1)
y = 4 + 3 * X + np.random.randn(100, 1)

# --- Hyperparameters ---
learning_rate = 0.05
epochs = 500
n_samples = X.shape[0]

# --- Initialize Parameters ---
w = np.random.randn(1, 1)
b = 0.0

# --- Training Loop ---
for epoch in range(epochs):
    # Forward Pass
    y_pred = X * w + b
    
    # Loss computation (MSE)
    loss = (1 / (2 * n_samples)) * np.sum((y_pred - y)**2)
    
    # Gradient Calculations
    dw = (1 / n_samples) * np.dot(X.T, (y_pred - y))
    db = (1 / n_samples) * np.sum(y_pred - y)
    
    # Gradient Parameter Updates
    w -= learning_rate * dw
    b -= learning_rate * db
    
    if epoch % 100 == 0:
        print(f"Epoch {epoch:03d} | MSE Loss = {loss:.4f} | w = {w[0][0]:.3f} | b = {b:.3f}")

Chapter 6: KNN Distance Engine & Scaling Effects Euclidean Scaling

Analytical Formulation: Euclidean distance between two spatial points: $d(\mathbf{p}, \mathbf{q}) = \sqrt{\sum (p_i - q_i)^2}$. Feature ranges bias distance: if dimension 1 has range $[0, 10000]$ and dimension 2 has range $[0, 1]$, dimension 1 dominates the calculations. Normalization ensures uniform attribution. 

import numpy as np

# Unscaled features: Column 0 (Income in $), Column 1 (Age in Years)
X_raw = np.array([[45000, 22], [85000, 48], [12000, 19], [92000, 52], [50000, 24]])
query_point = np.array([48000, 23])

# Euclidean distance function
def calculate_distances(X, query):
    return np.sqrt(np.sum((X - query)**2, axis=1))

# Scale features using Min-Max Normalization
def min_max_scale(X):
    col_min = X.min(axis=0)
    col_max = X.max(axis=0)
    return (X - col_min) / (col_max - col_min), col_min, col_max

# 1. Unscaled Distance Calculation
raw_distances = calculate_distances(X_raw, query_point)

# 2. Scaled Distance Calculation
X_scaled, min_val, max_val = min_max_scale(X_raw)
scaled_query = (query_point - min_val) / (max_val - min_val)
scaled_distances = calculate_distances(X_scaled, scaled_query)

# Display comparisons
print("Raw (Unscaled) Distances:", np.round(raw_distances, 1))
print("Scaled (Normalized) Dist:"); print(np.round(scaled_distances, 3))

Exercise 7: Naive Bayes Joint Probabilities & Laplace Smoothing Probability Classifier

Analytical Formulation: Naive Bayes calculates posterior category matches: $P(C \mid w_1, w_2) \propto P(C) \prod P(w_i \mid C)$. If word $w_i$ is unseen in class $C$, then $P(w_i \mid C) = 0$, collapsing the entire joint likelihood to zero. Laplace smoothing corrects this: $P(w_i \mid C) = \frac{count(w_i, C) + \alpha}{count(C) + \alpha \cdot V}$, where $V$ is vocabulary size. 

# Vocabulary: ['buy', 'now', 'meeting', 'review'] (V = 4)
# Class Counts: Spam has 10 words, Ham has 15 words
V_size = 4
spam_counts = {'buy': 6, 'now': 3, 'meeting': 1} # 'review' has 0 counts in spam
ham_counts = {'meeting': 8, 'review': 5, 'now': 2}  # 'buy' has 0 counts in ham

# Compute likelihood with Laplace smoothing (alpha = 1)
def compute_likelihood(word_count, total_words, vocab_size, alpha=1):
    return (word_count + alpha) / (total_words + alpha * vocab_size)

# Word to classify: "buy review"
# 1. Without Laplace smoothing (alpha = 0)
p_review_spam_raw = compute_likelihood(0, 10, V_size, alpha=0) # P("review"|Spam) = 0
p_buy_ham_raw = compute_likelihood(0, 15, V_size, alpha=0)     # P("buy"|Ham) = 0

# 2. With Laplace smoothing (alpha = 1)
p_buy_spam_smoothed = compute_likelihood(6, 10, V_size, alpha=1)
p_review_spam_smoothed = compute_likelihood(0, 10, V_size, alpha=1)
joint_spam = p_buy_spam_smoothed * p_review_spam_smoothed

p_buy_ham_smoothed = compute_likelihood(0, 15, V_size, alpha=1)
p_review_ham_smoothed = compute_likelihood(5, 15, V_size, alpha=1)
joint_ham = p_buy_ham_smoothed * p_review_ham_smoothed

print("Raw: P('review'|Spam) =", p_review_spam_raw, " | P('buy'|Ham) =", p_buy_ham_raw)
print("Smoothed Joint Spam Likelihood:", round(joint_spam, 4))
print("Smoothed Joint Ham Likelihood :", round(joint_ham, 4))

Analytical Observations: Without Laplace smoothing, the presence of a single novel word ("review" in spam or "buy" in ham) would set the entire joint likelihood product to exactly zero, rendering classification impossible. With Laplace smoothing, we assign a small non-zero probability weight to unseen features ($0.071$ in spam and $0.053$ in ham), enabling stable, relative probability score updates.

Learning Reflections

Reflection 1: What surprised me most during this course?

What surprised me most during this course was realizing that the most powerful machine learning models are heavily dependent on simple mathematical principles. Before taking this course, I viewed algorithms like gradient boosting and neural networks as complex black boxes that miraculously extracted insights from data. However, deriving linear regression and gradient descent updates from scratch showed me that these systems are essentially iterative exercises in vector calculus and linear algebra. Seeing how adjusting a learning rate or adding a regularization parameter changes the geometry of a loss surface was an eye-opening conceptual breakthrough. I was also surprised by how critical feature engineering is compared to model architecture sweeps. Creating a simple compound feature representing an individual's behavioral risk index yielded far greater classification gains than executing extensive hyperparameter grid searches. This realization shifted my focus from chasing complex models to understanding the physical and mathematical properties of feature representation.

Reflection 2: Most challenging concept and how I mastered it.

The most challenging concept I encountered was backpropagation in multi-layer neural networks, specifically tracking the chain rule across high-dimensional tensor matrices. Early on, I struggled to visualize how errors in the final output layer propagate backward to adjust weight matrices in early hidden layers. To master this, I took a step-by-step approach. First, I manually calculated the partial derivatives of a small network with two inputs, one hidden layer of two units, and one output unit using paper and pencil. I traced each partial derivative backward, verifying how the activation function's derivative scales the gradient. Once the analytical equations were clear, I programmed a simple feedforward network in raw Python, manually coding the forward and backward passes. Finally, I compared my custom gradient calculations against PyTorch's Autograd output on the synthetic Two Moons dataset. Tracing this mathematical pathway from manual derivations to code blocks and verifying it with modern automatic differentiation engines helped me gain a solid, intuitive command of backpropagation mechanics.

Domain & Objective

Predicting multi-label public health vaccination choices

Vaccination is a cornerstone strategy for combating infectious viral outbreaks. Determining who is likely to accept preventive treatments allows medical campaigns to optimize messaging and distribute vaccines effectively.

This project tackles a **Multi-label Binary Classification** problem using survey responses. We predict two parallel targets: whether a respondent received the H1N1 flu shot, and whether they received the Seasonal flu shot. The metrics rely on the **Area Under the Receiver Operating Characteristic Curve (AUROC)**.

Core Predictive Goals

Predict probabilities for:

  • h1n1_vaccine ∈ {0, 1} (Uptake: ~21.2%)
  • seasonal_vaccine ∈ {0, 1} (Uptake: ~46.6%)

Data Preprocessing & Balancing

Imputations, encoding strategies, and class balancing adjustments

Median & Unknown Imputation

Survey records have missing responses. To avoid row deletions:

  • Numerical missing columns are filled using the column's median value to prevent outlier skewing.
  • Categorical columns are filled using the label "Unknown".
Class Imbalance & SMOTE Variants

The H1N1 positive label exhibits a minority imbalance (only 21.2% received it):

  • Applied over-sampling using the smote_variants library during local training.
  • Synthetic samples were added for the H1N1 class to boost model sensitivity (recall) without overfitting.

High-Dimensional Encoding: Categorical variables (such as age_group, education, employment_occupation, etc.) were encoded using One-Hot encoding via pd.get_dummies(), which expanded the feature dimensions from 38 features to over 100 features.

Evaluation Strategy

Local cross-validation vs. competition leaderboard performance

To ensure robust generalization, models were evaluated using **Stratified 5-Fold Cross Validation** locally. This preserves the target class proportions in each fold, providing stable out-of-fold validation predictions.

Local Validation vs. Leaderboard Discrepancy: Our best ensemble pipeline achieved a local validation score of 0.8618 AUROC, while the official competition leaderboard returned a score of 0.8448 AUROC. This discrepancy is common in machine learning:

  • The local validation score represents out-of-fold evaluations on the training set, which benefit from feature alignment across folds.
  • The competition leaderboard evaluates predictions on a hidden test dataset that may contain slight distribution shifts.
  • This comparison demonstrates robust validation hygiene, showing that local cross-validation estimates remain high-fidelity predictors of model performance on unseen data.

Hyperparameter Tuning & Search

Bayesian optimization sweeps and parameter tuning diagnostics

Instead of standard grid searches, we implemented a **Bayesian Optimization** sweep using the Optuna library. Over 100 trials were run per model to identify optimal convergence parameters while maintaining generalization guards.

Tuning Insights

Restricting the max_depth to moderate values (5–7) and utilizing column sub-sampling (colsample_bytree) proved critical in stabilizing out-of-fold validation scores, effectively countering the model's tendency to overfit high-cardinality demographic columns.
